# 萃取状态机（Extraction State Machine）—— CJ·经验萃取 v2.0

把"对话式动态萃取"从**靠感觉追问**升级为**有状态、可判停、可续跑**的工程机制。核心是五层深度状态机 + 牛招识别判据 + 判停条件。

> 本文是 `question-tree.md`（追问方向菜单）的**执行层升级**：八大方向解决"问什么"，状态机解决"挖到哪一层、什么时候停、怎么记录"。

## 一、五层深度状态机

每次萃取，对一个"干法"按五层逐级下探。**目标是明确当前挖到哪一层，以及下一层该问什么。**

```
层级0 基操 Base    —— 谁都会的基本做法（不封）
层级1 方法 Method  —— 有顺序的步骤/流程（可封装骨架）
层级2 牛招 Killer  —— 只有他会的差异化打法（最值钱，深挖）
层级3 心法 Mindset —— 背后的判断逻辑/信念/假设（抽象层）
层级4 边界 Boundary —— 适用条件/失效条件/反例（防教条）
```

### 层级判定规则（听完一段回答，30 秒内归类）

| 回答特征 | 归入层级 | 下一步动作 |
| --- | --- | --- |
| 是常识、人人都会 | 层级0 基操 | 不封，继续找差异 |
| 有步骤、有顺序、能照着做 | 层级1 方法 | 追问动作与工具，向层级2 下探 |
| 有反直觉细节 / 和他人做法不同 / 有数据佐证 | 层级2 牛招 | **锁定，深挖到底** |
| 讲了判断依据、信念、为什么这么做 | 层级3 心法 | 追问"什么信号触发你这样做" |
| 讲了例外、失败、不适合谁 | 层级4 边界 | 记录反例，收敛封装 |

## 二、牛招识别判据（何时从"方法"升级为"牛招"）

不能靠感觉判断"这是牛招"。满足以下判据**至少 3 条**才标记为牛招并深挖：

| # | 判据 | 判断问题 |
| --- | --- | --- |
| 1 | **难复制** | 别人照着做，短时间内学不会？ |
| 2 | **反直觉** | 做法和常识/大多数人的直觉相反？ |
| 3 | **有失败对照** | 他吃过亏/见过别人栽在这上面？ |
| 4 | **有数据支撑** | 能说出量化结果（金额/转化/时间）？ |
| 5 | **差异显著** | 和同行做法有明显不同？ |

> **判据不足 3 条 → 只是方法，不是牛招**，正常封装即可，不额外深挖。
> 命中 ≥3 条 → 标记 `[牛招]`，用灵魂三问（差异/边界/迁移）连挖到底。

## 三、八大追问方向的判停条件（防止无限追问）

每个方向配"挖到底的标志"，到了就停，换方向或收敛：

| 方向 | 判停标志（挖到这样就够） |
| --- | --- |
| ① 拆解 | 能把大主题拆成可执行的 2-5 个小环节 |
| ② 还原场景 | 能还原到"时间/处境/难题/第一个动作"清晰可见 |
| ③ 挖动作 | 能一步接一步复述动作，含"先动哪步后动哪步" |
| ④ 挖工具 | 拿到可直接复用的模板/话术/清单（或明确没有） |
| ⑤ 挖验证 | 拿到可量化指标 + "怎么知道是它起的作用"的解释 |
| ⑥ 挖边界 | 拿到适用条件 + 至少 1 个反例/失效场景 |
| ⑦ 挖对标 | 明确"和别人做法的差异点"并能举例 |
| ⑧ 挖迁移 | 明确"能用到哪些其他场景"的最通用原则 |

## 四、对抗认知闭合（自动触发，不是靠自觉）

检测到被萃取者出现以下信号时，**强制回拉**：

| 信号 | 自动回拉话术 |
| --- | --- |
| 开始下结论（"其实关键就是要坚持"） | "先别急着下结论，回到当时那个动作上——你具体先做了哪一步？" |
| 讲得太泛（"我做了很多事"） | "我们把其中一件拎出来，拆到动作级，具体怎么做的？" |
| 跳过细节（"然后就这样了"） | "停一下，这一步中间有没有什么卡点？你当时是怎么处理的？" |
| 完美叙事（"一路都很顺"） | "有没有哪次差点没成？当时出了什么状况？" |

> 原则：**识别本能 → 抵制敷衍 → 拉长思考 → 深挖隐性**。对抗认知闭合是对话式萃取区别于"问答清单"的根本。

## 五、断点续跑（对话也可以断点）

- 每次萃取维护 `EXTRACTION_STATE.md`，记录：当前主题、每个干法到达的层级、待追问点、已确认项。
- 换会话/中断后，先读状态文件，从"该干法当前层级"继续下探，不重来。
- 状态示例：
```markdown
## 干法追踪
| 干法 | 当前层级 | 状态 | 待追问 |
| --- | --- | --- | --- |
| 种子用户陪建法 | 牛招(2) | 待挖心法 | 什么信号判断对方适合当"联创" |
| 冷启动三步 | 方法(1) | 待挖工具 | 那套开场话术能否还原 |
```

## 六、与 question-tree.md 的配合

- **question-tree.md** 负责：每轮给 2~5 个追问方向菜单（问什么）。
- **本状态机** 负责：判定回答层级、识别牛招、给出判停条件、维护状态（挖到哪、下一步问哪个方向）。
- 两者循环咬合：回答 → 归类层级 → 出菜单 → 自选方向 → 追问 → 更新状态 → 判停或继续。
