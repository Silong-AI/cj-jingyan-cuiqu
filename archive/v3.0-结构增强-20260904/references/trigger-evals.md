# 触发评测协议（Trigger & Output Evals）—— CJ·经验萃取 v2.1

把"质量红线"从**纸面规则**落地为**可执行的评测**：一套触发测试集（验证 skill 正确触发与分流）+ 一套产出质量评测（验证成果物达标）。每次萃取交付前跑一遍，不合格回炉。

> 对标 cangjie-skill 的 `run_trigger_evals.py` / `run_output_evals.py` 思想：质量不是靠自觉，是靠评测卡点。

## 一、触发评测（Trigger Evals）—— skill 用对了吗

### 1.1 触发测试集（10 例）

把以下输入喂给 skill，检查是否正确触发与分流。**任一例分流错误即未通过**：

| # | 输入 | 应触发 | 应分流到 |
| --- | --- | --- | --- |
| T1 | "帮我萃一下我们销冠的成功经验" | ✅ 触发 | 组织模式 |
| T2 | "想把老王做单子那套方法整理出来" | ✅ 触发 | 个人模式 |
| T3 | "团队新人上手太慢，怎么办" | ✅ 触发（模糊需求） | 场景诊断 → 组织模式 |
| T4 | "把我自己的经验沉淀成一个手册" | ✅ 触发 | 个人模式·萃自己 |
| T5 | "这段录音帮我整理成经验" | ✅ 触发（素材） | 素材萃取 → ai-assist |
| T6 | "萃一个电商大促复盘的经验" | ✅ 触发 | 复盘+萃取（组织/个人） |
| T7 | "写一封给客户的邮件" | ❌ 不触发 | 拒绝/换 skill |
| T8 | "帮我算一下这个月业绩" | ❌ 不触发 | 拒绝/换 skill |
| T9 | "培训课上怎么把销冠方法讲给新人" | ✅ 触发（弱信号） | 组织模式·教学封装 |
| T10 | "萃经验"（极简） | ✅ 触发 | 入口分流询问 |

**通过标准**：T1-T6、T9-T10 全部正确触发并分流到预期路径；T7-T8 不误触发。

### 1.2 萃取师 Voice Check（对话质量验证）★v2.2

CJ 的核心是"对话式动态萃取"，所以要检验**追问本身像不像专业萃取师**，而不只是流程对不对。抽取一轮真实的追问对话，逐项打分：

| 检查项 | 通过标准（像专业萃取师） | 不通过信号（像聊天机器人） |
| --- | --- | --- |
| 追问自然度 | 承接对方上一句、顺着语境追问 | 生硬跳题、套模板问句 |
| 对抗认知闭合 | 对方想总结时主动往回拉回动作层 | 礼貌附和、跟着对方思路走 |
| 菜单设计 | 2~5 个编号方向，方向有差异且对应回答类型 | 一次抛十几个问题、方向雷同 |
| 话术具体性 | "你第一步先动了哪一步？""当时怎么下的手？" | "能详细说说吗"这类空泛话 |
| 挖掘推进 | 每轮都在往更深一层走（方法→牛招→心法） | 反复问同一个层面的问题 |
| 金句保留 | 记录原话、原数字、原画面 | 只记结论、丢掉细节 |

**通过标准**：6 项 ≥5 项通过；<5 项则本轮追问需调整（回炉到"对话质量"维度，不直接交付）。

### 1.3 流程评测点（抽查 3 项）

对一次完整萃取，检查以下环节是否按 v2.0 规范执行：

| 检查项 | 通过标准 |
| --- | --- |
| 入口分流 | 30 秒内判断了个人/组织/共创/萃自己/模糊需求 |
| 档位确认 | 开跑前确认了快速/标准/深度 |
| 检查点 | 至少展示了 ①骨架 或 ②干法清单 其中一个检查点 |
| 状态机 | 对挖出的干法标了层级（方法/牛招/心法/边界） |
| 验证门禁 | 每条干法过了 V1/V2/V3 三重验证 |

## 二、产出质量评测（Output Evals）—— 成果达标吗

### 2.1 干法卡质量评测（每张卡 10 分）

| 维度 | 满分 | 评分标准 |
| --- | --- | --- |
| 一句话SOP | 2 | 含"如果…切忌…那么就…避开…从而"完整结构 |
| 适用场景+边界 | 2 | 有"适用/不适用"，不是万能药 |
| 步骤可操作 | 2 | 步骤含"动作+要点+常见错误"，新人能照着做 |
| 工具可复用 | 2 | 有可直接复用的模板/话术/清单 |
| 验证有依据 | 2 | 有指标、有来源（哪位高手/哪个案例/数据） |

**通过标准**：单卡 ≥8 分；<8 分回炉补缺项。

### 2.2 技能包质量评测（7 项清单）

| # | 检查项 | 结果 |
| --- | --- | --- |
| 1 | README 说清"给谁用/解决什么/怎么开始" | ☐ |
| 2 | 有 `skill-pack.yaml`（机器可读清单） | ☐ |
| 3 | 每条干法有稳定 `capability_id` | ☐ |
| 4 | 干法库每条过了三重验证（标注 V1/V2/V3） | ☐ |
| 5 | 训练包覆盖训战闭环（训/演/战/盘） | ☐ |
| 6 | 验证包含试点方案与考核表 | ☐ |
| 7 | DIGEST 一页能讲清价值 | ☐ |

**通过标准**：7 项全过才可交付；缺任一项回炉。

### 2.3 自动化校验（可选脚本）

若产出为本地目录，可用 `scripts/validate_skill_pack.py` 自动校验技能包结构（README/干法卡/manifest/DIGEST 是否齐全、frontmatter 是否规范）。详见脚本说明。

## 三、回炉规则

- **触发评测未过**：检查 description 触发词与入口分流逻辑，修正后再测。
- **干法卡 <8 分**：回到萃取阶段补挖"动作/工具/验证"三层，不直接改评分。
- **Voice Check 未过**：调整追问话术与菜单设计，重测一轮对话质量。
- **技能包 7 项缺**：补齐对应模块，不跳过交付。
- **回炉上限（★v2.2）**：每个技能包最多回炉 **2 次**；2 轮后仍有薄弱项，标注薄弱维度并交付当前最优版，不无限打磨（质量红线第 8 条）。
- **评测结果留痕**：把每次评测结果写入 `EVAL_REPORT.md`（通过项/失败项/修复记录），形成质量轨迹。
