# 可安装团队技能包（Team Skill Pack）—— CJ·经验萃取 v2.2

把一次萃取从"一篇文档"升级为**一个可安装、可训练、可验证的团队技能包**。技能包是可交付的组织资产：团队拿到就能训、就能用、就能验证。

> 对标 cangjie-skill 的 compile 思想，但语境是**组织**：产出物不是给 AI Agent 调用的代码级 skill，而是给"人 + 培训体系"直接用的能力包。

## 一、技能包结构

```
主题技能包：<场景名>（如：新客开发）
├── README.md               # 一页说明：给谁用 / 解决什么 / 怎么开始
├── skill-pack.yaml         # 技能包清单（机器可读，生态对齐）★v2.1
├── test-prompts.json       # 评测用例（darwin 兼容）★v2.1
├── 打法库/                  # 验证通过的打法清单（核心）
│   ├── 打法-01-<名称>.md     # 一张打法卡
│   ├── 打法-02-<名称>.md
│   └── 打法索引.md           # 总览表 + 优先级
├── 成果物/
│   ├── SOP.md               # 标准动作（含步骤+要点+反例）
│   ├── 话术库.md             # 可复用的原话/话术
│   ├── 工具包/               # 模板/清单/打分表
│   └── 案例库/               # STAR 案例（含数据/对标/金句）
├── 训练包/
│   ├── 课程大纲.md           # 集中学习
│   ├── 演练剧本.md           # 角色扮演+标准话术+反馈
│   └── 带教陪跑计划.md        # 每周死磕一个关键行为
├── 验证包/
│   ├── 试点方案.md           # A/B 对照设计
│   └── 考核表.md             # 怎么算学会了 / 有效了
└── DIGEST.md               # 一页精华：给决策者看的总结
```

> **★v2.1 生态对齐**：`skill-pack.yaml` 是机器可读清单（pack_id / capabilities / verification / compatible_with），`test-prompts.json` 是评测用例（可喂 darwin 进化）。完整规范见 `ecosystem-alignment.md`。可用 `scripts/validate_skill_pack.py` 自动校验本结构是否齐全。
>
> **★v2.2 工程化校验**：① `skill-pack.yaml` 由 `schemas/skill-pack.schema.json`（JSON Schema）做深度校验——level 只能是"基操/方法/牛招/心法/边界"，capabilities 每项必含 id/file 且文件存在，pack_id 必须小写连字符；② 打法库索引由 `scripts/generate_index.py` 自动生成（读打法卡 frontmatter 汇总），不手写；③ 回归测试 `scripts/test_validate_schema.py` 验证"非法 manifest 会被拦截"。

## 二、打法卡模板（每个打法一张）

```markdown
# 打法：<名称>（给方法起个易记的名字）

**一句话**：<如果（情境）…切忌（反例）…那么就（动作）…避开（坑）…从而（结果）>

**适用场景**：<什么时候用>
**不适用**：<边界/反例>

## 步骤
| 步骤 | 关键动作 | 要点/技巧 | 常见错误 |
| --- | --- | --- | --- |

## 关键工具
<模板/话术/清单，直接可复制>

## 验证
- 指标：<怎么量化有效>
- 证据：<来自哪位高手 / 哪个案例 / 数据>
- 层级：[牛招/方法/心法]（来自状态机判定）

## 迁移
<这招还能用在哪些场景>
```

## 三、DIGEST 精华模板（给决策者）

```markdown
# <场景> 经验萃取 · 精华摘要

**一句话结论**：<核心打法一句话>

**三大关键打法**：
1. <打法名> —— <一句话>
2. <打法名> —— <一句话>
3. <打法名> —— <一句话>

**可验证收益**：<预期指标：转化率/客单价/上手时间>

**落地方式**：<培训 → 演练 → 实战 → 带教 → 复盘>

**验证计划**：<试点团队 + 对照 + 周期>
```

## 四、技能包质量标准（交付前逐项过）

- [ ] README 说清"给谁用 / 解决什么 / 怎么开始"
- [ ] 每条打法过了三重验证门禁
- [ ] 每张打法卡含：一句话 SOP + 步骤 + 工具 + 验证
- [ ] 成果物通过"成果校验清单"（见 `verification-gates.md`）
- [ ] 训练包覆盖"训战闭环"（不是只有课程 PPT）
- [ ] 验证包含试点方案与考核表
- [ ] DIGEST 一页能讲清价值

## 五、与原有封装模板的关系

- `packaging-templates.md`（v1）负责"单条打法/单个成果"的封装形式（SOP/口诀/案例/课程）。
- 本文件负责"整套组织资产"的打包结构（技能包 = 打法库 + 成果物 + 训练包 + 验证包）。
- 建议：个人萃取用 `packaging-templates.md`；**组织级项目直接产出技能包**，个人经验包是其基础单元。
