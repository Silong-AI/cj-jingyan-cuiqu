# CJ·经验萃取（Experience Extraction）v2.0

把"人会做但说不清"的经验，变成"看得见、学得会、用得着、验证过"的资产。核心信念：**经验 = 经历 + 干法 + 被验证的成功**；萃取的目标不是记录故事，而是提炼出"可复制的干法"。

> **v2.0 相比 v1.0 的升级**：① 入口分流 + 档位管理 + 检查点（不跑偏、不失控）；② 五层萃取状态机 + 牛招识别判据（挖得更准）；③ 三重验证门禁 + 落地验证协议（证明有效）；④ 可安装团队技能包（产出即落地）。原版所有方法论与战法完整保留。

## 何时使用（入口分流）

收到"萃经验"需求后，**先走 `references/entry-routing.md` 做入口分流**，再落对应路径：

- 用户要萃取某个人（专家/销冠/老员工/自己）在某领域的成功经验 → **个人模式** `references/mode-individual.md`
- 用户要给企业/团队（如销售）做组织级经验萃取与复制 → **组织模式** `references/mode-organization.md`
- 只有模糊需求（"想让团队更会卖货"）→ 先做**场景诊断**（`references/entry-routing.md`）
- 需要准备访谈问题清单 → `references/interview-question-bank.md`
- **需要做"动态对话、用户自选追问方向"的深挖访谈 → 先读 `references/question-tree.md`（追问决策树）+ `references/extraction-state-machine.md`（五层状态机/牛招判据/判停条件）**
- **需要对萃取结果做验证 → `references/verification-gates.md`（三重验证门禁 + 落地验证协议）**
- **组织级项目要产出可落地资产 → `references/skill-pack-template.md`（可安装团队技能包）**
- 需要补充具体战法（SBP敏捷萃取/三阶萃取/训战六步/复盘工具族/一纸禅等）→ `references/method-library.md`
- 需要把萃取结果封装成成果物（先按"三问"选成果形式）→ `references/packaging-templates.md`
- 需要借助 AI 加速萃取（转写、聚类、建模）→ `references/ai-assist.md`

## 核心原则（9+4 条）

1. **经验=经历+干法+被验证**：只萃取"做成过且有效"的经验；未经验证的设想不算经验。
2. **挖细节不挖观点**：高手往往说不出"为什么成功"，但一定说得出"具体怎么做的"。追问方法/动作/工具/窍门。
3. **鲜活案例自带转化力**：用 STAR/SCQA 还原真实场景，案例要有数据、有对标、有金句。
4. **萃取四原则**：有经验必萃取、有萃取必验证、验证后必固化、固化后必迭代。
5. **先框架后细节**：先定场景与对象，再逐层深挖，最后封装；不漫谈。
6. **萃取必有用**：每次萃取都要回答"给谁用、解决什么问题、用在哪里"；没有使用场景就不萃。
7. **80%目标**：目标不是让普通人成为高手，而是"让80%的普通人拥有高手80%的能力、达到60分的水平"。
8. **内萃外取**：向内萃自己的高手，向外借鉴国际与国内一些专业的经验萃取方法论，两者结合做场景化。
9. **问得越多挖得越深（对话式动态萃取）**：经验藏在细节里，每多追问一层就多一层可复制的部分。每轮给出 2~5 个追问方向（编号菜单），由被萃取者自选，选一个方向挖到底再换方向，循环直到区分出"基操与牛招"。
10. **v2·先分流再萃取**：30 秒内完成入口分流与档位确认，不跑偏、不失控。
11. **v2·有状态地挖**：用五层状态机记录"挖到哪一层"，用牛招判据识别"什么值得深挖"，到判停条件就收敛。
12. **v2·验证先行**：每条干法封装前过三重验证门禁，落地前有验证协议，用数据说话。
13. **v2·产出即落地**：组织级萃取直接产出"可安装团队技能包"，让团队拿到就能训、就能用。

## 主流程：定 → 萃 → 验 → 用

### 一、定（定向组局 + 入口分流）
- **入口分流**（`entry-routing.md`）：先判断个人/组织/团队共创/萃自己/模糊需求，走对应路径。
- **场景诊断**（模糊需求时）：从业务问题反推"萃什么、萃谁、产出什么、怎么验证"。
- **档位确认**：快速 / 标准 / 深度，控制成本与深度。
- 定**场景**：萃什么主题？解决什么业务问题？（如"如何开发大客户"）
- 定**人**：找谁萃？（高手筛选标准见下）
- 定**对象**：经验给谁用？用到哪里？
- 定**局**：组局方式（访谈/工作坊/共创会），谁主持、谁记录、多长时间。
- **检查点①**：展示"萃取设计一页纸"让用户确认。

高手筛选三高模型（组织模式）：绩效持续领先（持续而非偶然）+ 有具体案例/细节/画面（讲得出故事）+ 有分享热情（愿意带人）。

### 二、萃（对话式动态萃取 / 共创深挖）
- **核心机制：动态追问决策树 + 五层状态机**。每听完一段回答：
  1. **归类层级**：基操/方法/牛招/心法/边界（`extraction-state-machine.md`）；
  2. **识别牛招**：用 5 条判据（难复制/反直觉/有失败对照/有数据/差异显著）判断是否值得深挖；
  3. **出编号菜单**：从八大追问方向（拆解/还原场景/挖动作/挖工具/挖验证/挖边界/挖对标/挖迁移）挑 2~5 个，**由被萃取者自选**；
  4. **按判停条件**决定挖到底还是收敛；
  5. **更新状态文件**（`EXTRACTION_STATE.md`），支持断点续跑。
  - 完整机制与话术见 `references/extraction-state-machine.md` + `references/question-tree.md`。
- 问题清单与常用框架：`references/interview-question-bank.md`；STAR、SCQA、ORID/OID、鱼骨图、4D 发现法。
- 具体战法按需取用：SBP敏捷萃取、三阶萃取、训战六步"启萃训演战盘"、GRAI/CSS复盘、一纸禅等见 `references/method-library.md`。
- 多人共创时用团队经验提现法（见组织模式），打破"经验孤岛/师徒困境/场景茧房"三大黑洞。
- **检查点②**：每轮深挖后展示"已挖出的干法清单"让用户确认。

### 三、验（验证门禁 + 落地验证）
- **三重验证门禁**（`verification-gates.md`）：每个候选干法过 V1 跨域复现 / V2 预测力 / V3 独特性；不过的降级或淘汰，留审计。
- **成果校验清单**：SOP/课程/案例库在封装前逐项过"必含要素"清单。
- **检查点③**：展示"通过 N 条 + 淘汰 M 条"让用户确认。
- **落地验证协议**（组织模式）：试点 A/B 对照、SOP 可用性测试（新人照着做能否 60 分）、冲突仲裁、经验过期检测。

### 四、用（封装输出 + 落地推广）
- **先按"三问选择器"**（给谁看×要达成什么×发在哪）定成果形式（沉淀/传播/教学/工具/变现/组织），再按 `references/packaging-templates.md` 封装。
- **组织级项目直接产出"可安装团队技能包"**（`references/skill-pack-template.md`）：干法库 + 成果物 + 训练包 + 验证包 + DIGEST。
- **检查点④**：成果物形态与结构预览，用户确认后交付。
- 验证：小范围试用 → 看结果 → 迭代；验证有效才固化推广。
- 推广：训战结合（训练-演练-实战-带教-复盘），"我说你听→我做你看→你做我看→你做我看你复盘"。
- 迭代：固化后持续迭代，防止经验过期。

## 标准四环（组织级项目建议按此推进）

1. **定向组局**：定场景/人/对象/局，组团队（5-8人最佳）。
2. **访谈萃取**：还原场景、深挖要点（方法/动作/工具/窍门）、反思意图、探询可能；用状态机+追问决策树推进。
3. **验证封装**：三重验证门禁 → 成果校验 → 主题包装、内容建模、口诀编撰、工具打磨、公式建立、话术书写、形成案例（成果7步法）。
4. **验证推广**：试点验证 → 训战落地 → 晾晒机制 → 迭代复制。

## 质量红线（v2，违反则阻止输出）

1. 每一条进入成果的干法，必须通过三重验证门禁（V1/V2/V3）。
2. 每个成果物必须通过"成果校验清单"（动作+工具+口诀+验证标准等必含要素）。
3. 组织级产出必须是"可安装团队技能包"结构，而非散文档。
4. 重要结论必须可追溯：能回到原访谈/原案例/数据（保留原始语言与金句）。
5. 标出适用边界与信息截止时间，不夸大普适性。
6. 不编造经验：AI 产出只是草稿，关键判断必须由专家/高手本人确认。

## 操作总则

- 全程引导式提问，多用"能不能举个例子""具体怎么做""当时怎么想的"，少用"你觉得原因是什么"。
- **动态对话优先**：每轮听完回答给 2~5 个追问方向菜单（编号①②③…），请被萃取者自选；选一个方向挖到底再换。见 `references/question-tree.md`。
- **对抗认知闭合**：被萃取者急着总结时往回拉，"先别急着下结论，回到当时那个动作上"。识别本能→抵制敷衍→拉长思考→深挖隐性。
- **一次聚焦一个场景/一个关键行为**，避免泛泛而谈。
- **记录时保留原始语言和金句**，封装时再加工成模型语言。
- **输出成果物时**，按用户偏好控制篇幅与形式（结构化清单/可视化/文档均可）。
- **长流程可断点续跑**：维护 `EXTRACTION_STATE.md`，中断后从断点继续。

## 复盘+萃取增强（大会案例融合）

- **萃取之前必复盘**：复盘是找到"真牛人、牛事、牛招及萃取点"的捷径（不盘不萃不会）。
- 复盘+萃取时机矩阵（边战边萃·战萃一体·战传合一）与结构化四步复盘法（回顾目标→评估策略→反思过程→总结规律），详见 `references/mode-organization.md` 的"复盘+萃取战法"。
- 萃取师 6感模型（共情/设计/故事/交响/娱乐/意义）与"AI没有右脑/不懂场域/没有行动力"灵魂三问，详见 `references/ai-assist.md`。
- 三段式故事框架问题清单、亮点法、NLP逻辑层次、淘宝原则、深挖牛招牛刀牛气，详见 `references/interview-question-bank.md`。
